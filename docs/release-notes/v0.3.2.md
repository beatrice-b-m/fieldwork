# Fieldwork 0.3.2

Fieldwork 0.3.2 adds `relate` for checking how two tables (or a table and
itself) connect through a key, restyles figures and reports so colour encodes
results only, and keeps more qualitative evidence in topology exports.
Fieldwork's own error messages no longer quote source values, and an opt-in
`safe_errors` control keeps third-party messages out too. Saved results remain
schema 2.0; new fields are additive. Some finding statements and overview lead
order change (see Changed). Python 3.11–3.14 remains supported; pandas and
NumPy remain the only required runtime dependencies.

## Added

- `relate(left, right, on=..., compare=...)` checks two tables without joining
  them: key coverage in each direction, matched-key cardinality (`1:1`, `1:n`,
  `n:1`, `n:m`), agreement of compared attributes and, with `right=None`,
  reciprocity of a self-reference. Every answer is a count-free state with
  measurements in full output. Each side keeps its own scope, sentinels and
  table ID. Values match numerically by default (`match="typed"`) or also as
  integer text (`match="text"`), and key or compared columns whose value kinds
  do not overlap raise a `VALUE_KIND_MISMATCH` warning. `Result.inspect` and
  `select` take `side=` and `right=` for relation results; `recompute` and
  `Recipe.run` take `right=`. `fieldwork.typing` adds `MatchMode`, `Side` and
  `RelateLimits` ([relating two tables](../contracts.md#relating-two-tables),
  [definitions](../algorithms.md#relations-across-tables)) (#23).
- Runtime control `safe_errors=True` raises any failure as
  `fieldwork.AnalysisError`, naming only the operation, innermost phase, column
  when known and original exception type, so pandas, NumPy or Python messages
  that quote cells cannot leave the environment. Cancellation, keyboard
  interrupts and progress-callback errors propagate unchanged
  ([runtime controls](../performance.md#keep-source-values-out-of-error-messages))
  (#20).
- `joint_counts` accepts `min_count`: cells counting fewer rows are omitted,
  together with axis values that only omitted cells support. Full output reports
  the omitted cells and rows, topology marks the omission, and `max_cells`
  applies to the reported grid (#19).
- `value_patterns` accepts `min_count` to omit formats, lengths and prefixes
  seen in fewer rows. String pattern findings record their reported formats in
  `structure`, sorted and without counts, plus whether others were omitted;
  topology keeps them and still drops lengths and prefixes (#18).
- `render_svg`, `render_html` and `visualization_data` accept `shading`
  (`fieldwork.typing.Shading`) to choose how association and joint-count cells
  are split into four ranges: `"equal"`, `"log"`, `"quantile"` or three fixed
  cut-offs. Full-detail pairs and joint-count projections record the cut-offs
  used under `shading` ([shading ranges](../output-ux.md#shading-ranges)).

## Changed

- Figures and reports are restyled. Figures draw on white with dark outlines,
  system fonts (identifiers in monospace), orthogonal grain-map connectors and
  fixed-place legends. Colour now encodes results only: blue for determined
  (constant, n:1), orange for varying (varying, 1:n), a dark fill for 1:1,
  dashed outlines for absent or out-of-scope cells, and a four-range scale for
  amounts that adapts to each figure. HTML reports follow the viewer's light or
  dark scheme, keep figures on white, and remain offline
  ([colour and type](../output-ux.md#colour-and-type)).
- Column availability findings in `missingness` state whether a column is
  populated in some or no units (`X: populated in some rows`, `X: populated in
  no rows`) and record it as `structure["presence"]` (`"some"` or `"none"`).
  Availability families record the same state (`Same availability (populated
  in no rows): a, b`). Context availability findings state whether all, some or
  none of the context's units are populated, likewise in the statement and
  `structure["presence"]`. Topology exports therefore distinguish always-missing
  columns from partially populated ones. Complete columns are still not
  findings. Code that matched the previous statements, `X: populated values`
  and `Same availability: ...`, must be updated; finding IDs are unchanged
  (#14, #22).
- Entity presence patterns that match no entity are no longer findings; the
  entity summary still counts them (#14).
- Approximate dependencies are stated as "X approximately determines Y", and
  approximate availability implications as "approximately implies", so
  plain-text topology keeps the distinction from exact ones (#16).
- Dependency and availability findings record `structure["strength"]`
  (`exact` or `approximate`). Dependency findings and grain tests record
  `repeated_support`, so exact rules that hold only because every determinant
  group is one row are visible without counts. Standalone dependency and grain
  topology keep candidate and key roles, and text, SVG and HTML show them
  (#15, #17).
- Overview leads no longer rank an approximate dependency as a top "near-rule
  with exceptions" merely because one repeated determinant group exists. Its
  repeated rows must cover at least a quarter of evaluated rows and agree with
  the modal rule in at least 90% of them; other near-rules score 0.3 with the
  reason "near-rule with sparse repeated support". Lead order and `lead`
  annotations can therefore change; section findings and their IDs do not
  ([overview lead ranking](../algorithms.md#overview-lead-ranking)) (#27).
- Fieldwork's own error messages name columns, arguments and value types, never
  source cell values: an unsupported cell is reported by its type, and a pairs
  reference domain that misses observed levels reports how many (#20).
