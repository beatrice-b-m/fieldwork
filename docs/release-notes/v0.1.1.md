# Fieldwork 0.1.1

Fieldwork 0.1.1 adds runtime controls for larger tables and makes the support
behind dependency findings easier to assess. Python 3.11–3.14 remains supported;
NumPy and pandas remain the only required runtime dependencies.

## Changes since 0.1.0

- Follow dataframe analyses with `progress=True` or a `ProgressEvent` callback.
  `CancellationToken`, `AnalysisCancelled`, and `timeout` provide cooperative
  cancellation. The default stays silent; cancellation never returns a partial
  result as though it were complete.
- Choose automatic overview `sections` and `section_options`. Dependency discovery
  adds `include_grain`, `max_grain_views`, and `max_dependency_tests` so graph and
  dependency work can be bounded independently. Untested relationships remain
  unknown rather than negative evidence.
- Reduce repeated fingerprinting, encoding, grouping, and selection work with
  call-scoped, bounded caches and vectorized kernels. Source identity and
  population accounting remain exact; no row sampling is introduced. See the
  [measured workloads](../performance-results.md) for costs and limitations.
- Save repeated result containers with `to_dict(compact=True)` and restore them
  through the existing result loaders. Ordinary exports remain the default;
  compact exports use a separate versioned envelope and retain all evidence.
- Inspect dependency `target_coverage`, `repeat_coverage`, and
  `repeat_modal_accuracy`, with their explicit row counts. Exactness on singleton
  groups is preserved while distinguished from consistency supported by repeated
  groups. Candidate summaries include `determines_with_repeated_support` and
  `global_targets_tested` / `global_targets_possible`.
- Full summaries rank candidates within existing roles by repeated-supported exact
  target count, followed by determinant repeated rows, key size, and lexical order.
  Raw exact-target count no longer gives singleton-only mappings a ranking advantage.
  This is descriptive ranking, not a reliability or entity-validity guarantee.
- Full dependency renderings show completed tests below `min_accuracy`. Saved
  schema-1.0 results render without source data; recoverable repeat measurements
  are derived, and unavailable legacy coverage is identified. Topology remains
  free of the new measurements and uses canonical ordering.
- Public APIs now have NumPy-style inline documentation, discoverable typed
  signatures (including forwarded options and runtime controls), reusable option
  types in `fieldwork.typing`, and documentation/editor regression checks.
- The guided investigation notebook, wide laboratory-table example, and new sparse
  dependency example have executable checks and regenerated presentation assets.

## Compatibility and interpretation

Discovery schema remains 1.0 and foundation schema remains 0.3. Existing analytical
measurements, finding IDs, candidate enumeration, source selectors, and compatible
population graph behavior are preserved. New dependency fields are additive;
undefined ratios serialize as JSON null. Full presentation ordering and content
intentionally change. Search budgets and feature order can still affect results.

With `dropna=False`, missing values participate as a category in consistency tests;
observed target coverage still records absence. Candidate repeated rows refer to
the determinant population; each dependency's repeated rows refer to its own
population after target exclusions. Exact mappings, repeated consistency, and
meaningful entities are distinct concepts.

Cancellation occurs between work items rather than interrupting a running
pandas/NumPy operation. Full-source identity validation still scans the source;
feature selection and scopes reduce analytical work, not that validation boundary.
Compact export reduces serialized repetition, not analysis memory.
